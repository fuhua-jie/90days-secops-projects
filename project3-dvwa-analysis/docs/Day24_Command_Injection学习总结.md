# Day24_Command_Injection学习总结

## 一、漏洞本质

**Command Injection（命令注入）**：应用程序将用户输入拼接到系统命令字符串中执行，攻击者通过注入操作系统命令连接符来追加恶意命令。

DVWA 场景：`shell_exec('ping ' . $target)`，用户控制 `$target`。

---

## 二、三级递进总览

| 级别 | 防御方式 | 能否绕过 | 绕过手法 |
|------|---------|---------|---------|
| Low | 无过滤 | ✅ | 直接拼接 `127.0.0.1 && whoami` |
| Medium | 黑名单 `str_replace` 过滤 `&&` 和 `;` | ✅ | 3种：`&`、`\|`、`&;&` 字符重组 |
| High | 黑名单过滤 `&` `;` `\|\|` `\| ` `-` `$` `()` `` ` `` | ✅ | 管道符不加空格：`127.0.0.1\|whoami` |

---

## 三、各级别详解

### Low 级

```php
$target = $_REQUEST['ip'];
$cmd = shell_exec('ping ' . $target);
```

- **零防护**：用户输入直接拼入命令字符串
- **注入**：`127.0.0.1 && whoami` → `ping 127.0.0.1 && whoami` → 两个命令都执行
- **学习点**：命令注入最基础的形态 —— 信任用户输入就是灾难

### Medium 级

```php
$substitutions = array('&&' => '', ';' => '');
$target = str_replace(array_keys($substitutions), $substitutions, $target);
```

- **防御**：黑名单删除 `&&` 和 `;`
- **缺陷**：`str_replace` 只做字符删除，不做语义分析

**三种绕过：**

| 输入 | 过滤后 | 实际执行 | 原理 |
|------|--------|---------|------|
| `127.0.0.1 & whoami` | 不变（`&`不在黑名单） | `ping 127.0.0.1 & whoami` | 单 `&` 未过滤 |
| `127.0.0.1 \| whoami` | 不变（`\|`不在黑名单） | `ping 127.0.0.1 \| whoami` | 管道符未过滤 |
| `127.0.0.1 &;& whoami` | `127.0.0.1 && whoami` | `ping 127.0.0.1 && whoami` | **字符重组**：`;`被删，`&`+`&`→`&&` |

**关键洞察 —— 黑名单 `str_replace` 的两大缺陷：**

1. **遗漏**：总能找到不在黑名单中的替代字符（`&` 替代 `&&`，`|` 替代 `;`）
2. **字符重组**：删除操作可能让剩余字符拼出新的危险序列（`&;&` → `&&`）

**常见陷阱**：`127.0.0.1 && whoami` 在 Medium 级看起来"被拦截"了，实际是 `&&` 被删后命令变成 `ping 127.0.0.1 whoami`，`whoami` 被 ping 当成主机名解析失败，根本不是在执行命令注入。输出乱码是因为 GBK 编码的中文报错信息被 UTF-8 页面错误解码。

### High 级

```php
$substitutions = array(
    '||' => '',   // 过滤 OR 连接符
    '&'  => '',   // 过滤所有 & 系列
    ';'  => '',   // 过滤分号
    '| ' => '',   // 过滤"管道+空格"
    '-'  => '',   // 过滤命令选项
    '$'  => '',   // 过滤变量展开
    '('  => '',   // 过滤左括号
    ')'  => '',   // 过滤右括号
    '`'  => '',   // 过滤反引号
);
```

- **防御**：9 项黑名单，几乎封死了所有已知路径
- **致命疏漏**：`'| '` 只过滤管道后跟空格的情况

**绕过：**
```
127.0.0.1|whoami
```
管道符紧贴命令，不加空格，`'| '` 模式不匹配，原样保留。

**执行结果对比：**

| 输入 | 过滤后 | 结果 |
|------|--------|------|
| `127.0.0.1\| whoami` | `127.0.0.1whoami`（`\| `被删） | ❌ ping 找不到主机 |
| `127.0.0.1\|whoami` | `127.0.0.1\|whoami`（不变） | ✅ whoami 输出用户名 |

## 四、Windows 命令连接符速查

| 连接符 | 含义 | Windows | Linux |
|--------|------|---------|-------|
| `&&` | 前命令成功才执行后命令 | ✅ | ✅ |
| `&` | 前后都执行，不管成败 | ✅ | ❌（后台运行） |
| `\|\|` | 前命令失败才执行后命令 | ✅ | ✅ |
| `\|` | 管道：前命令 stdout → 后命令 stdin | ✅ | ✅ |
| `;` | 顺序执行 | ❌ | ✅ |

**注意**：`;` 是 Linux 专属，Windows cmd 不支持。Medium 级过滤 `;` 在 Windows 环境下其实没有实际威胁，但 `str_replace` 删除 `;` 反而可能制造字符重组攻击。

---

## 五、核心学习方法论

1. **先读源码，再动手**：不看源码的黑盒测试是盲猜，看了源码才知道黑名单精确写了什么
2. **理解过滤机制而非记忆 payload**：`str_replace` 的删除语义 vs 正则匹配的拒绝语义，本质不同
3. **字符重组是黑名单的天然缺陷**：删除字符后剩余字符可能拼出新语义，这是 `str_replace` 黑名单绕不过去的坑
4. **空格是攻击者的朋友**：`'| '` 和 `'|'` 的差异，一个空格决定成败
5. **管道环境下命令行为可能改变**：`net user` 在管道中静默失败，不代表绕过失败

---

## 六、防御启示

| 做法 | 效果 |
|------|------|
| 黑名单 `str_replace` | ❌ 永远有遗漏 + 字符重组风险 |
| 白名单（只允许数字+点） | ✅ 从根源杜绝 |
| `escapeshellarg()` | ✅ PHP 内置转义 |
| 不用 `shell_exec`，用 `exec` 函数参数化 | ✅ 最佳实践 |

---

## 七、从 Low 到 High 的感悟

- **Low**：不设防，入侵者直接进门
- **Medium**：在门上贴了"禁止入内"的纸条，但纸条可以撕掉，撕掉后还能拼出"欢迎光临"
- **High**：换了密码锁，但留了一条缝 —— 管道符紧贴命令就能钻进去

**真正的安全不是堵住已知路径，而是从根本上消除命令拼接的可能性。**
