DVWA-命令注入

- 命令注入的含义

和 SQL 注入原理一模一样，只是拼接的目标不同：

SQL 注入：   用户输入 → 拼接到 SQL 语句 → 数据库执行

命令注入：   用户输入 → 拼接到系统命令   → 操作系统执行

举个最直观的例子：

// DVWA 的逻辑（伪代码）

$cmd = "ping " . $_REQUEST['ip'];   // 用户输入直接拼到命令里

system($cmd);                        // 执行系统命令

// 正常使用：输入 192.168.1.1

// 执行：ping 192.168.1.1  ✅ 正常

// 恶意输入：192.168.1.1 && whoami

// 执行：ping 192.168.1.1 && whoami  💀 命令注入！

//              ping 完  →  再执行 whoami → 返回当前用户名

核心知识：操作系统命令连接符

命令注入的"语法"就是 OS 命令连接符：

| 连接符 | 含义 | Windows | Linux |
|---|---|---|---|
| && | 前面的命令成功后才执行后面的 | ✅ | ✅ |
| & | 前面执行完就执行后面的（不管成败） | ✅ | ✅ |
| \|\| | 前面的命令失败才执行后面的 | ✅ | ✅ |
| \| | 把前面的输出传给后面的（管道） | ✅ | ✅ |
| ; | 前面执行完执行后面的 | ❌ | ✅ |

注意：; 是 Linux 专属，Windows cmd 不支持。Medium 级过滤 ; 在 Windows 环境下其实没有实际威胁，但 str_replace删除 ;反而可能制造字符重组攻击。

- Medium级

- 源码分析

![](images/5-DVWA-命令注入学习/5-DVWA-命令注入学习_004.png)

核心源码：

// ① 获取用户输入

$target = $_REQUEST['ip'];

// ② 黑名单过滤

$substitutions = array( '&&' => '', ';' => '' );

$target = str_replace( array_keys($substitutions), $substitutions, $target );

// ③ 拼接并执行

$cmd = shell_exec( 'ping ' . $target );

过滤逻辑：把 && 和  ;  替换成空，即删除。

漏洞：黑名单只拦了 2 个连接符，还有一堆没拦！（&、|、||等等都没删）

- 绕过方法

输入 127.0.0.1 && whoami

![](images/5-DVWA-命令注入学习/5-DVWA-命令注入学习_005.png)

输入的 127.0.0.1 && whoami 经过 str_replace 处理：

| 步骤 | 内容 |
|---|---|
| 原始输入 | 127.0.0.1 && whoami |
| && 被替换成空字符串 | 127.0.0.1  whoami（中间两个空格） |
| 实际执行的命令 | ping  127.0.0.1  whoami |

注意：

- && 是连接符整体被删除，whoami 并没有被独立成命令，而是变成了 ping 的"第二个参数"。

- 在 Windows 下执行 ping 127.0.0.1 whoami，ping 把第一个非选项参数后面的内容也当成主机名解析，发现 whoami 不是一个可解析的 DNS 名，于是直接输出错误信息并退出，根本没去 ping 127.0.0.1

输入127.0.0.1 & whoami      ← 单个 & 没被过滤！

![](images/5-DVWA-命令注入学习/5-DVWA-命令注入学习_006.png)

输入 127.0.0.1 | whoami      ← 管道 | 没被过滤！

![](images/5-DVWA-命令注入学习/5-DVWA-命令注入学习_007.png)

因为  |  的含义是将前面命令的结果输出给后面命令所以显示的只要whoami

输入 127.0.0.1 &;& whoami

![](images/5-DVWA-命令注入学习/5-DVWA-命令注入学习_008.png)

;  被删 → 变成 127.0.0.1 && whoami → && 执行！

- High级

- 源码分析

![](images/5-DVWA-命令注入学习/5-DVWA-命令注入学习_009.png)

'||' => '',    // 过滤 OR

'&'  => '',    // 过滤单 &（& 和 && 和 & & 全死）

';'  => '',    // 过滤分号

'| ' => '',    // 过滤"管道+空格"

'-'  => '',    // 过滤短横线（禁用命令选项）

'$'  => '',    // 过滤 $（禁用变量展开）

'('  => '',    // 过滤左括号

')'  => '',    // 过滤右括号

'`'  => '',    // 过滤反引号

| 被过滤的 | 杀掉了什么 |
|---|---|
| & | `&`、`&&`、`& &`、`&;&` 全部阵亡 |
| ; | 分号分隔 |
| \|\| | OR 连接符 |
| \| | 管道+空格 |
| - | 所有命令选项（`-la`、`-c`、`-n` 等） |
| $  () | `$()` 命令替换 |
| ` | 反引号命令替换 |

看得出来，开发者几乎封死了所有已知的 Medium 绕过路径。

🔑 但有一个致命疏漏

仔细看这一行：

'| ' => '',    // 管道+空格

它过滤了 | （管道后面跟一个空格），没有过滤单独的 | 字符。

也就是说：

| 输入 | str_replace 后 | 实际执行 | 结果 |
|---|---|---|---|
| 127.0.0.1\| whoami | 127.0.0.1whoami（\|  被删） | ping 127.0.0.1whoami | ❌ 失败 |
| 127.0.0.1\|whoami | 127.0.0.1\|whoami（没有\|  模式） | ping 127.0.0.1\|whoami | ✅ 成功 |

管道符紧贴命令，不加空格，就绕过了。

- 正确尝试

输入 127.0.0.1|whoami

![](images/5-DVWA-命令注入学习/5-DVWA-命令注入学习_011.png)

str_replace 从头扫到尾：

\|\| — 不匹配（只有一个 |）

& — 不匹配

; — 不匹配

\|  — 不匹配（| 后面是 w，不是空格）

- — 不匹配

... 全部不匹配

最终 $target 原样保留为 127.0.0.1|whoami

在 Windows cmd 中，| 把左边命令的 stdout 管道给右边命令的 stdin。whoami 不读 stdin，直接输出用户名，ping 的输出被管道吞掉。所以你会看到：只有 whoami 的结果，没有 ping 的 4 行回复。

掌握了管道无空格绕过之后，可以试：

- 127.0.0.1|dir

- 127.0.0.1|net user

注意：由于 - 被过滤，dir /a-d 这种带短横线的选项会变成 dir /a（-d 被去掉）。所以尽量用不需要选项的命令。

dir在windows相当于Linux的ls ，也就是列出目录内容的命令

- 总结

- 漏洞本质

Command Injection（命令注入）：

应用程序将用户输入拼接到系统命令字符串中执行，攻击者通过注入操作系统命令连接符来追加恶意命令。

DVWA 场景：shell_exec('ping ' . $target)，用户控制 $target。

- 三级递进总览

| 级别 | 防御方式 | 能否绕过 | 绕过手法 |
|---|---|---|---|
| Low | 无过滤 | ✅ | 直接拼接 127.0.0.1 && whoami |
| Medium | 黑名单 str_replace过滤 &&和 ; | ✅ | 3种：&、\|、&;&字符重组 |
| High | 黑名单过滤 & ; \|\| \|  - $ () ` | ✅ | 管道符不加空格：127.0.0.1\|whoami |

- 各级别详解

- Low级

$target = $_REQUEST['ip'];

$cmd = shell_exec('ping ' . $target);

- 零防护：用户输入直接拼入命令字符串

- 注入：127.0.0.1 && whoami→ping 127.0.0.1 && whoami→两个命令都执行

- 学习点：命令注入最基础的形态 —— 信任用户输入就是灾难

- Medium 级

$substitutions = array('&&' => '', ';' => '');

$target = str_replace(array_keys($substitutions), $substitutions, $target);

防御：黑名单删除 &&和 ;

缺陷：str_replace只做字符删除，不做语义分析

三种绕过：

| 输入 | 过滤后 | 实际执行 | 原理 |
|---|---|---|---|
| 127.0.0.1 & whoami | 不变（&不在黑名单） | ping 127.0.0.1 & whoami | 单 &未过滤 |
| 127.0.0.1 \| whoami | 不变（\|不在黑名单） | ping 127.0.0.1 \| whoami | 管道符未过滤 |
| 127.0.0.1 &;& whoami | 127.0.0.1 && whoami | ping 127.0.0.1 && whoami | 字符重组：;被删，&+&→&& |

关键洞察 —— 黑名单 str_replace的两大缺陷：

- 遗漏：总能找到不在黑名单中的替代字符（&替代 &&，|替代 ;）

- 字符重组：删除操作可能让剩余字符拼出新的危险序列（&;&→ &&）

常见陷阱：127.0.0.1 && whoami在 Medium 级看起来"被拦截"了，实际是 &&被删后命令变成 ping 127.0.0.1 whoami，whoami被 ping 当成主机名解析失败，根本不是在执行命令注入。输出乱码是因为 GBK 编码的中文报错信息被 UTF-8 页面错误解码。

- High 级

- 防御：9 项黑名单，几乎封死了所有已知路径

- 致命疏漏：| 只过滤管道后跟空格的情况

绕过：

- 127.0.0.1|whoami

管道符紧贴命令，不加空格，| 模式不匹配，原样保留

- 核心学习方法论

- 先读源码，再动手：不看源码的黑盒测试是盲猜，看了源码才知道黑名单精确写了什么

- 理解过滤机制而非记忆 payload：str_replace的删除语义 vs 正则匹配的拒绝语义，本质不同

- 字符重组是黑名单的天然缺陷：删除字符后剩余字符可能拼出新语义，这是 str_replace黑名单绕不过去的坑

- 空格是攻击者的朋友：'| '和 '|'的差异，一个空格决定成败

- 管道环境下命令行为可能改变：net user在管道中静默失败，不代表绕过失败

- 防御启示

| 做法 | 效果 |
|---|---|
| 黑名单 str_replace | ❌永远有遗漏 + 字符重组风险 |
| 白名单（只允许数字+点） | ✅从根源杜绝 |
| escapeshellarg() | ✅PHP 内置转义 |
| 不用 shell_exec，用 exec函数参数化 | ✅最佳实践 |

- 从 Low 到 High 的感悟

- Low：不设防，入侵者直接进门

- Medium：在门上贴了"禁止入内"的纸条，但纸条可以撕掉，撕掉后还能拼出"欢迎光临"

- High：换了密码锁，但留了一条缝 —— 管道符紧贴命令就能钻进去

真正的安全不是堵住已知路径，而是从根本上消除命令拼接的可能性。

- 源码

$target = stripslashes( $target );

$octet = explode( ".", $target );            // 按点拆成4段

if( is_numeric( $octet[0] ) && ... && is_numeric( $octet[3] ) && sizeof( $octet ) == 4 ) {

$cmd = shell_exec( 'ping  ' . $target );

逻辑：强制输入必须形如 数字.数字.数字.数字（4 段全是纯数字），然后重新拼接成干净的 IP。任何注入字符都会被 is_numeric 拦截。你输入 8.8.8.8;whoami → $octet[3] 是 8;whoami → is_numeric('8;whoami') 为 false → 直接报 ERROR: You have entered an invalid IP.

- 四个级别总结

| 级别 | 输入（payload） | 预期结果 |
|---|---|---|
| Low | 127.0.0.1 & whoami | 先 ping 输出，再显示 target-host\www-data |
| Medium | 127.0.0.1 & whoami | 成功（& 没被拦） |
| High | 127.0.0.1 \|whoami（无空格） | 成功；;、& 会被拦 |
| Impossible | 127.0.0.1 & whoami | 报 ERROR: You have entered an invalid IP.（被拒） |
